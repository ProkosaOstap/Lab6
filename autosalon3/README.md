# Автосалон — лабораторна - 6: RESTful API (Node.js)

Проєкт продовжує роботу «Автосалон» і додає **захищену область** — панель
керування `/panel`, де авторизований користувач з необхідними повноваженнями
(ролі «менеджер» або «адміністратор») може керувати даними всіх таблиць
системи: додавати, змінювати та видаляти записи.

## RESTful API

Повний RESTful API для доступу до даних системи та керування ними
(модуль `api.js`, всі відповіді — JSON). Таблиці: `brands`, `trims`,
`clients`, `options`, `sales`.

| Метод і шлях | Дія | Доступ |
|---|---|---|
| `GET /api` | опис ендпоінтів | всім |
| `GET /api/:table` | список записів | всім |
| `GET /api/:table/:id` | один запис | всім |
| `POST /api/:table` | створення запису | manager / admin |
| `PUT /api/:table/:id` | оновлення запису | manager / admin |
| `DELETE /api/:table/:id` | видалення запису | manager / admin |

**Авторизація**: сесія браузера або заголовок `Authorization: Basic логін:пароль`
(для API-клієнтів, наприклад `curl -u manager:manager123`).

**Коди відповідей**: 200 OK, 201 Created, 400 — помилки валідації
(`{ "error": "...", "errors": { поле: текст } }`), 401 — не авторизовано,
403 — заборонено для ролі, 404 — не знайдено, 409 — видалення заблоковане
посиланнями інших таблиць.

**Приклади**:

```bash
# список марок
curl http://localhost:3000/api/brands

# створити марку (manager/admin)
curl -u manager:manager123 -X POST http://localhost:3000/api/brands \
     -H "Content-Type: application/json" \
     -d '{"name": "Fiat", "country": "Італія"}'

# оновити клієнта
curl -u admin:admin123 -X PUT http://localhost:3000/api/clients/2 \
     -H "Content-Type: application/json" \
     -d '{"full_name": "Ковальчук І. П.", "phone": "+380509876543", "email": "iryna.k@example.com"}'

# продаж із вибраними опціями (зв'язок M:N — масив id опцій)
curl -u manager:manager123 -X POST http://localhost:3000/api/sales \
     -H "Content-Type: application/json" \
     -d '{"client_id": 2, "trim_id": 2, "sale_date": "2025-11-01", "discount": 7, "options": [1, 4]}'

# видалити запис
curl -u manager:manager123 -X DELETE http://localhost:3000/api/brands/5
```

У продажах API повертає розширені поля: `options` (масив id вибраних
опцій), `client_name`, `trim_name`; у комплектаціях — `brand_name`.

Валідація в API та у веб-формах — спільний модуль (`entities.validateEntity`):
ті самі правила (обов'язковість, формати, унікальність, зовнішні ключі).

## Структура доступу

**Публічна область** (головна сторінка та списки `/brands`, `/trims`,
`/clients`, `/sales`, `/options`):
- гість і відвідувач — лише перегляд (без кнопок редагування);
- менеджер і адміністратор — кнопки додавання/зміни/видалення прямо у списках.

**Захищена область — панель керування `/panel`** (окрема зона для
користувачів з повноваженнями):
- гість → перенаправлення на `/login`;
- відвідувач → 403 (недостатньо повноважень);
- менеджер → керування всіма таблицями автосалону;
- адміністратор → те саме + керування користувачами (`/panel/users`).

Усі операції керування (створення, редагування, видалення і форми)
доступні і за звичайними шляхами (`/brands`, `/brands/1/edit` ...), і всередині
панелі (`/panel/brands`, `/panel/brands/1/edit` ...) — і в обох випадках
захищені middleware перевірки ролі на сервері.

## Що додано у цій частині

- Головна сторінка панелі `/panel` з переліком усіх таблиць,
  кількістю записів і швидкими діями
- Усі маршрути керування даними перенесено в захищену область `/panel/...`
- Публічні списки тепер суто переглядові для всіх ролей
- Керування користувачами — у `/panel/users` (лише адміністратор)
- У меню з'являється посилання «Панель керування» для менеджера й адміністратора

## Структура проєкту

| Файл | Призначення |
|---|---|
| `server.js` | Express-сервер: публічна область + захищена панель `/panel`, сесії, Passport, валідація |
| `auth.js` | Стратегія Passport, middleware захисту за ролями |
| `entities.js` | Опис сутностей: поля, типи, валідатори, правила видалення |
| `validators.js` | Бібліотека валідаторів |
| `views.js` | HTML-шаблони (списки, форми, вхід/реєстрація, панель, користувачі) |
| `api.js` | RESTful API: JSON-ендпоінти `/api/...`, Basic-автентифікація |
| `db.js` | Файлове JSON-сховище (`data/db.json`, створюється автоматично) |

## Серверна валідація

У HTML-формах **немає жодного атрибута `required`** — усі перевірки
виконуються на сервері: обов'язковість, довжина, діапазони, формати
(телефон, email, дата), унікальність, зовнішні ключі, посилальна
цілісність при видаленні. При помилках форма повертається з введеними
значеннями та повідомленнями українською (HTTP 400).

Railway сам виконує `npm install` і `npm start`; порт читається зі змінної `PORT`.
Тестові акаунти (admin/admin123, manager/manager123, visitor/visitor123) вже є у файловій базі.

**Збереження даних.** Записи зберігаються у `data/db.json` усередині контейнера.
Щоб дані не зникали після передеплою: **Settings -> Volumes** (mount path `/data`)
та змінна `DATA_DIR=/data` у **Variables**.
